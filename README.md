# Customer Churn Prediction

**Author:** Akashdeep Singh
**Project Name:** customer_churn  

---

## Overview

A complete end-to-end Data Analytics and Machine Learning project that predicts customer churn using real-world subscription data. The project covers data cleaning, exploratory data analysis (5 charts with insights), binary classification modelling (Logistic Regression + Random Forest), full model evaluation, and actionable business recommendations with a resource-constrained prioritisation strategy.

---

## Dataset

| Property | Value |
|----------|-------|
| **File** | `customer_churn_dataset.csv` |
| **Rows** | 64,374 |
| **Columns** | 12 |
| **Target** | `Churn` (0 = Retained, 1 = Churned) |
| **Missing Values** | None |
| **Duplicates** | None |
| **Class Balance** | ~52.6% Retained / ~47.4% Churned |

### Columns

| Column | Type | Description |
|--------|------|-------------|
| CustomerID | int | Unique identifier (dropped in ML) |
| Age | int | Customer age (18–65) |
| Gender | str | Male / Female |
| Tenure | int | Months as a subscriber |
| Usage Frequency | int | Service usage count |
| Support Calls | int | Number of support calls |
| Payment Delay | int | Days of payment delay |
| Subscription Type | str | Basic / Standard / Premium |
| Contract Length | str | Monthly / Quarterly / Annual |
| Total Spend | int | Total $ spent |
| Last Interaction | int | Days since last interaction |
| Churn | int | **Target** — 1=Churned, 0=Retained |

## Setup & Run Instructions

### 1. Clone / Download the project

Place all files in the same directory.

### 2. Create a virtual environment (recommended)

```bash
python -m venv venv
# Windows
venv\Scripts\activate
# macOS / Linux
source venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Launch Jupyter Notebook

```bash
jupyter notebook YashSharma_customer_churn_dataset.ipynb
```

Or using JupyterLab:

```bash
jupyter lab YashSharma_customer_churn_dataset.ipynb
```

### 5. Run all cells

Use **Kernel → Restart & Run All** to execute the full pipeline from top to bottom.

## Top Business Insights

1. **Monthly contracts** have the highest churn rate — offer annual upgrades early.
2. **5+ support calls** is a strong churn signal — trigger proactive outreach at call #4.
3. **Payment delay > 15 days** — intervene with flexible payment options before cancellation.
4. **Basic-tier subscribers** churn most — a 90-day upgrade trial can shift perceived value.
5. **ML risk tiers** — score customers monthly and allocate retention budget by tier:
   - `P(Churn) ≥ 0.70` → High Risk: dedicated CSM + personalised offer
   - `P(Churn) 0.45–0.70` → Medium Risk: automated campaign
   - `P(Churn) < 0.45` → Low Risk: standard comms only

## Notes

- `CustomerID` is dropped before ML training (raw identifier — no predictive value, target leakage risk).
- An 80/20 **stratified** train-test split is used to preserve class balance.
- Decision threshold can be tuned below 0.50 to increase recall (catching more churners) at the cost of some precision.
- The model should be retrained quarterly as customer behaviour evolves.
